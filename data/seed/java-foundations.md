# Java 基础复习资料

## Object.equals 与 hashCode

如果两个对象通过 equals 判断相等，它们必须返回相同的 hashCode。反过来，两个对象 hashCode 相同并不能证明 equals 相等，因为哈希冲突是允许的。重写 equals 时通常也应重写 hashCode，避免哈希集合无法按预期查找相等对象。

## String 不可变性

Java String 对象创建后，其表示的字符序列不能原地修改。对字符串执行拼接等操作会得到新的字符串结果。不可变值可以安全共享，也适合作为哈希映射键；大量循环拼接通常应使用 StringBuilder。

## 重载与重写

重载发生在同一作用域中，方法名相同而参数列表不同，选择哪个重载主要由编译期参数类型决定。重写是子类为继承来的实例方法提供实现，运行时会按实际对象类型进行动态分派；返回类型需满足兼容规则，访问权限不能缩小。

## Java 内存模型与 volatile

volatile 写入与之后对同一变量的 volatile 读取建立 happens-before 关系，可用于发布最新值并保证可见性。volatile 不会把复合的读改写操作自动变成原子操作，因此 `count++` 不能仅靠 volatile 保证并发安全。

## synchronized

synchronized 使用监视器提供互斥，并对同一监视器的解锁与后续加锁建立 happens-before 关系。保护复合状态时，它能让临界区按互斥方式执行；锁的范围和共享对象选择仍需谨慎。

## HashMap

HashMap 根据键的哈希值定位桶，再使用相等性判断寻找具体键。哈希冲突时多个键可能落入同一桶。容量不足时会扩容并重新安排桶。它不是线程安全容器；并发读写应选择合适的并发容器或同步策略。

## ArrayList 与 LinkedList

ArrayList 以可增长数组保存元素，按索引读取通常是常数时间，尾部追加的均摊成本较低，中间插入和删除会移动后续元素。LinkedList 是双向链表，按索引访问需要遍历；只有已经持有目标节点且插入删除频繁时，节点调整才便宜。

## JVM 运行时数据区

线程私有的数据区包括程序计数器、Java 虚拟机栈和本地方法栈。堆与方法区属于线程共享区域。对象通常分配在堆中，但具体分配方式受虚拟机实现和优化影响。

## 垃圾回收

Java GC 回收的是不再被可达对象引用的对象，而不是简单地回收“离开作用域的变量”。可达性分析从 GC Roots 开始遍历引用关系。局部变量作用域结束不等同于其引用在任意时刻都立即消失。

## TCP 三次握手

建立 TCP 连接时，客户端发送 SYN，服务端以 SYN-ACK 响应，客户端再 ACK。双方由此确认初始序列号并建立连接状态。三次消息并不是简单重复两次，而是让双方都能确认双向收发能力。

## HTTP 与 HTTPS

HTTP 定义应用层请求与响应语义。HTTPS 是在 HTTP 通信中使用 TLS 提供传输加密、完整性保护和服务端身份验证。加密并不自动保证业务接口的授权和输入校验正确。

## 数据库索引

索引能减少满足条件时需要检查的数据范围，但会占用存储并增加写入维护成本。多列索引的列顺序影响可利用的查询前缀。是否使用索引还取决于选择性、统计信息和执行计划。

## 事务 ACID

ACID 分别描述原子性、一致性、隔离性和持久性。隔离级别会影响并发事务能观察到的现象；数据库实现、锁或 MVCC 策略会影响具体行为。不能只用“事务就是同时成功或失败”概括全部 ACID。

# 前端八股复习

## JavaScript 事件循环

浏览器把同步代码先放入当前调用栈；微任务通常在当前任务结束后、下一次宏任务开始前清空。Promise 回调属于微任务，定时器回调属于任务队列。面试时要先说明运行环境和队列规则，再按入队顺序推导输出。

## 浏览器缓存与网络

强缓存由 Cache-Control、Expires 等响应信息控制；协商缓存通过 ETag 或 Last-Modified 让浏览器向服务端确认资源是否变化。缓存策略需要和资源版本化、用户数据安全以及 CDN 行为一起考虑，不能简单地把所有响应都设成长缓存。

## CSS 布局与渲染

Flex 更适合一维排列，Grid 更适合二维区域；布局问题应先确认包含块、尺寸约束和溢出规则，再处理对齐。浏览器渲染通常经历样式计算、布局、绘制和合成，频繁读取布局信息并写入样式可能造成强制同步布局。

# 后端与服务设计

## 幂等与重试

网络请求可能超时但服务端已经处理成功。创建类接口可使用幂等键记录请求结果，重试策略应设置上限、退避和抖动，并区分可重试的瞬时错误与业务校验错误。

## 缓存与一致性

缓存能降低读取延迟和数据库压力，但会引入过期、穿透、击穿和雪崩问题。常见做法包括 TTL、空值缓存、互斥重建和随机过期；写入路径要明确先更新数据库还是先删除缓存，以及失败后的补偿方式。

## 消息队列语义

至少一次投递意味着消费者可能重复收到消息，因此业务处理应设计幂等。顺序、重试、死信和消费进度是不同问题；不能用“队列保证可靠”替代对确认、持久化和故障恢复的具体说明。

# Go 八股复习

## Goroutine 与 channel

Goroutine 是由运行时调度的轻量执行单元，channel 用于在并发任务之间传递值和同步。无缓冲 channel 的发送与接收需要配对，关闭 channel 表示不会再发送，不等于取消消费者；关闭已关闭的 channel 会触发 panic。

## Context 取消传播

context.Context 用于传递截止时间、取消信号和请求范围内的少量元数据。创建的 cancel 函数应及时调用，长期任务应在 select 中监听 Done；不要把 context 当作通用参数容器或可变配置存储。

## 接口与错误

Go 接口由方法集合隐式实现，较小的接口更容易组合和测试。错误应保留可判断的语义，调用方可以用 errors.Is 或 errors.As 检查原因；只拼接字符串会丢失结构化信息。

# Python 八股复习

## 可变对象与名称绑定

Python 变量是名称绑定，不是固定类型的盒子。list、dict 等可变对象被多个名称引用时，原地修改会被所有引用观察到；函数默认参数在定义时求值，不能把可变默认值当作每次调用的新容器。

## GIL 与并发模型

CPython 的 GIL 会限制同一进程中多个线程同时执行 Python 字节码，但 I/O 等待时线程仍可能交替推进。CPU 密集型任务可考虑多进程或释放 GIL 的扩展；异步事件循环适合大量可等待的 I/O，不会自动把同步 CPU 代码变快。

## 生成器与异步

生成器通过 yield 延迟产生值，适合流式处理并控制内存。async/await 需要事件循环驱动可等待对象；把阻塞调用直接放入事件循环会阻塞其他协程，应使用异步库或线程池隔离。

# AI 基础复习

## 过拟合与评估

过拟合表示模型记住训练样本而泛化能力不足。训练、验证、测试集应保持职责分离，调参不能反复窥视测试集。除了准确率，还要按类别不平衡和业务代价选择 precision、recall、F1、校准或任务特定指标。

## Transformer 注意力

自注意力根据查询、键和值计算加权组合，能让序列中不同位置建立依赖关系。多头注意力使用多个投影子空间，位置编码补充顺序信息；复杂度和上下文长度会影响推理成本。

## RAG 检索增强

RAG 先从资料库检索候选片段，再把片段交给生成模型回答。质量取决于切分、召回、重排、上下文预算和引用策略；检索命中不等于答案正确，应检查引用是否真正支持结论。

# Agent 八股复习

## 工具调用闭环

典型 Agent 循环包括理解任务、选择工具、执行并观察结果、更新状态和判断是否结束。工具协议要限制参数、超时和权限，循环必须有步数或预算上限，不能让模型无限自调用。

## 记忆与状态

短期上下文用于当前任务，长期记忆需要明确写入条件、检索范围和删除策略。把所有历史对话无界追加会增加成本并污染上下文；记忆内容还应区分用户事实、工具结果和模型推断。

## 提示注入与权限

外部网页、文件和工具返回值都可能包含诱导模型越权的文本。系统提示不能替代权限控制；应对工具做最小授权、参数校验、敏感操作确认和审计，并把不可信内容与指令分层处理。

# 计算机考研 408 复习

## 数据结构复杂度

分析算法时先明确基本操作、输入规模和最坏或平均情形。数组按下标访问通常为常数时间，平衡搜索树的高度与对数规模相关；复杂度结论必须和数据结构的不变量及实现条件对应。

## 操作系统进程与线程

进程拥有独立地址空间和资源边界，线程共享进程内的大部分地址空间但有自己的栈和寄存器上下文。并发题要区分调度、同步、互斥和通信，死锁分析通常围绕互斥、占有且等待、不可剥夺和循环等待四个条件。

## 计算机网络分层

分层模型帮助定位协议职责：链路层处理相邻节点传输，网络层负责寻址与路由，传输层提供端到端语义，应用层定义业务协议。回答 TCP、HTTP 等问题时应说明所在层和它依赖的下层能力。

# 软考复习

## 需求与架构

需求分析要区分功能、质量属性、约束和验收条件。架构决策应记录上下文、候选方案、权衡和后果；高可用、性能、安全和可维护性之间通常存在取舍，不能只写“使用微服务”作为架构理由。

## 项目管理与风险

进度、成本、范围和质量相互影响。风险登记应包含概率、影响、责任人、应对策略和触发条件；风险发生后的问题处理与事前风险应对不是同一类工作。

## 软件质量与测试

测试计划应覆盖单元、集成、系统和验收等层次，并说明可追踪的质量目标。代码评审、静态分析、持续集成和缺陷复盘属于质量保证活动，不能只依赖上线后的人工测试。
