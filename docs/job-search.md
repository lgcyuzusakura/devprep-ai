# 求职工作台

在侧边栏打开「求职工作台」，地址为 <http://127.0.0.1:8765/#/jobs>。核心结果是每个岗位可取走的专属简历与沟通话术，可以用来手动投递。

## 从通用简历生成岗位材料

1. 点击「通用简历」，粘贴完整简历，或导入 PDF、DOCX、UTF-8 TXT、Markdown（最大 2MB；扫描 PDF 请先 OCR）。也可读取「简历修改」工作区中某份简历的最新版本。
2. 补充项目职责、测试环境、成果口径与写作偏好，保存母版。需要自定义格式或从零编写时，可以先在「简历修改」里完成，再读取为母版。
3. 点击「新岗位」，填写岗位名称、公司、原始链接和完整 JD，按需写本岗位的要求，例如「优先展示缓存项目，教育背景放后面」。点击「生成专属简历与话术」会先保存岗位，再调用当前配置的模型。
4. 在「专属材料」查看完整中文简历、招聘聊天开场白、岗位自我介绍与跟进草稿。展开匹配依据，可看 JD 要求对应的原文、缺口与修改取舍。
5. 可以直接复制内容；也可编辑正文与话术，另存为新版本。下载支持 Word、Markdown、话术 TXT 和整套 ZIP。下载时有未保存的材料修改，会先另存一版。
6. 到招聘网站核对材料后投递，在「投递记录」登记实际进展和使用的版本。材料可送入「模拟面试」，携带该版本的 JD 和简历，准备定向面试；跳转本身不会调用模型。

母版不会被岗位改写覆盖。每次生成保存当时的母版、JD 和岗位信息；修改母版或岗位后，旧材料仍能按原公司、原岗位导出。手动修改会产生新版本，不覆盖旧稿。新版本的额外附件需重新添加，防止误沿用旧材料。

个人事实依据来自母版和补充事实，JD 不作为候选人经历。模型结果会检查原文引用、改写对应关系及新增数字；这不能证明经历真实，也不能完全检测语义上的夸大，投递前仍需核对。当前采用单次结构化生成，不输出虚假的 ATS 匹配率。

## 找岗位与导入

「找岗位」提供 BOSS直聘、牛客、猎聘、智联、前程无忧、LinkedIn 入口；可保存自己的 HTTPS 招聘链接。自定义来源入口保存在当前浏览器，岗位、母版、材料与记录保存在本机数据库。

公开岗位列表可直接预览这些公司招聘页，每次最多 200 条，再按关键词筛选并逐条收藏：

- `https://jobs.lever.co/公司标识`
- `https://job-boards.greenhouse.io/公司标识`（也支持 `boards.greenhouse.io`）
- `https://jobs.ashbyhq.com/公司标识`

这些适配器只读固定的公开 ATS API，禁止重定向和任意服务器抓取。公司名可能是招聘页的标识，请收藏后核对。读取失败、需要登录或不支持的网站，可以直接粘贴 JD 或使用浏览器助手。国内招聘平台未提供通用公开搜索接口，本版本不声称自动跨站搜索全部岗位。

相同岗位链接会阻止重复收藏；不同追踪参数可能视为不同链接，请优先保留规范岗位 URL。导入只是草稿和收藏，不会投递。

## 浏览器助手

仓库根目录的 `browser-helper/` 是 Chrome/Edge Manifest V3 扩展。无需 Node、Java 或额外模型，也不读取 Cookie、密码或完整浏览历史。

1. Chrome 打开 `chrome://extensions/`，Edge 打开 `edge://extensions/`，启用开发者模式。
2. 选择「加载已解压的扩展」，选中源码根目录的 `browser-helper` 文件夹。迁移包中位置为 `source/browser-helper`。
3. 在招聘岗位页选中 JD，打开扩展，点击「读取当前页面」。没有选中文字时读取页面正文；请移除导航、广告等内容。
4. 工作台地址保持 `http://127.0.0.1:8765`，如改过端口则相应调整。点击「导入DevPrep草稿」，在新标签页核对职位、公司和 JD 后保存。
5. 生成话术后复制到扩展的文本框。先在招聘网页点击目标输入框，再打开扩展，点击「填入网页当前输入框」。已有内容不会覆盖，密码等字段不处理；嵌套 iframe、自定义组件或受限页面可能不支持，请手动粘贴。

助手只在用户点击时访问当前标签页；不在后台抓站、不注入模型生成的脚本。草稿通过本机页面的 URL fragment 转入，页面读取后清除参数；不会向后端扩展开放通用 CORS。扩展保存的设置仅有本机工作台地址。

当前版本提供页面读取、草稿导入和明确触发的文本填写。文件上传、发送消息、最终投递由用户在招聘网站完成；尚未做多站点自动投递队列，无法保证任何平台实际收件。工作台不会把点击、下载或辅助填写标成「已投递」。

## 附件与进展

每份材料版本最多 5 个附件，每个最大 2MB，支持 PDF、DOCX、TXT、MD。附件只能在该版本的 ZIP 中下载；移除附件不影响其他版本。ZIP 包含：

- `resume.docx`、`resume.md`
- `messages.txt`：开场白、自我介绍、跟进草稿
- `job-and-version.json`：原岗位 JD、版本、模型与修改依据
- `attachments/`：该版本添加的文件

母版及工作稿属于私人数据，保存在现有 `/data` 数据库，不会写入源码或公开 Git 仓库。下载的材料含个人信息，请自行保管。草稿恢复使用当前浏览器的本地存储；清除站点数据会清除未保存草稿。

进展包括已收藏、材料就绪、已沟通、已投递、面试中、收到 Offer、未通过、已归档。登记「材料就绪」「已沟通」「已投递」需要选择属于该岗位的材料版本。

## 模型与部署

沿用模型设置中的 Codex 风格 TOML、网关和模型列表发现，不引入专用服务或另一份密钥。所有模型请求共用全局串行协调器，完成后默认间隔 10 秒；请选自己配置的 GPT 模型。生成失败不会覆盖母版、丢失收藏或产生虚假的成功材料。

Docker 更新会通过 Flyway V10 建立求职模块表，沿用已有数据卷。更新前可按 [使用指南](usage.md) 备份数据目录。源码部署执行 `docker compose up -d --build --wait --wait-timeout 180`。公开仓库和私人迁移包都不应包含本人简历、附件、投递记录或密钥。
