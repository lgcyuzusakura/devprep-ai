# 简历修改

打开 `/#/resume`。普通修改分析叙事、技术细节、个人贡献与信息顺序；JD 定向修改会同时分析岗位的核心要求、加分项和已有经历证据。没有 JD 时不会输出假定的岗位匹配分数。

## 使用流程

已有简历可以直接导入；没有旧稿时打开“从零编写简历 / 查看方向示例”，填写姓名、联系方式与章节草稿，再创建独立工作稿。自主编写、排版、保存、导出均不需要模型或密钥。

在正文完成编辑后，可点击“正文作为新材料”同步到左侧原始简历，再重新分析或做 JD 定向改写。它会替换原始材料，已有历史版本继续保留。

1. 粘贴原始简历，或导入 PDF、DOCX、UTF-8 TXT、Markdown（最多 2 MB、30,000 字，PDF 最多 20 页）。扫描 PDF 需要先 OCR。文件提取在本机完成。
2. 按需粘贴 JD，填写修改偏好，点击“分析简历”。诊断会展示亮点、弱项取舍、原文证据、信息顺序和需要补充的问题。
3. 回答关键追问，加入补充材料。可开启“增强设想”：系统提出适合现有项目规模的增强表述，附成立前提、验证方法和面试追问。点击采用后才进入补充材料，可自行调整数值和统计口径。
4. 点击“生成改写稿”。逐条查看原表达、改写后和修改原因，再编辑正文、保存新版本。
5. 导出 Word、Markdown，或使用浏览器打印保存 PDF。正文有编辑时，导出会先保存一个新版本。打印仅包含简历正文。

## 版式、章节和扩写

提供工程标准、一页紧凑、书面叙事、技术项目、极简文字五种版式，另可调整字体、字号、段落留白和标题颜色。版式选择随每个版本持久保存，Word 与打印输出使用相应设置；Markdown 导出保留内容与章节顺序，不携带视觉样式。各平台字体和 Word 排版引擎可能导致分页差异，“一页紧凑”不会强行删减内容以保证一页。

正文使用 Markdown 二级标题（`## 项目经历`）划分章节，章节可上移、下移，教育背景、校园经历可以放到最后；也可以添加自定义章节、直接编辑标题与正文。一级标题一般用于姓名，三级标题用于单段经历。

“AI 局部扩写”支持在编辑器中选中一段，或粘贴待扩写内容，填写扩写要求。系统结合原材料和 JD 返回扩写建议、理由与需确认的前提。结果不会自动覆盖正文，只有用户采用后才替换唯一对应段落或追加。采用记录和检查项进入补充材料，下一次保存或导出时留在版本快照中。

## 方向示例

内置八份 AI 辅助原创虚构示例：Java 后端、Go 后端、前端、Python、AI 应用、Agent、测试开发、运维/云原生。每份附写法说明，示范如何描述个人贡献、技术取舍、测量环境、故障恢复或具体交付。示例不是实际求职者简历或真实业绩；可以复制成独立工作稿后逐段替换为自己的经历。示例代码与文本可放在公开仓库，不包含本机个人简历。

增强设想属于用户采用的未核验材料。系统核对原文引用和数值是否来自输入，不证明经历真实，也不会检查材料内所有语义矛盾。数值不足时可以写交付物、覆盖场景、设计取舍、修复的问题，无须强加百分比。身份信息、学校、单位、任职时间与证书应由用户核对。

## 保存与请求行为

工作稿、诊断、历史版本和生成时的原始材料快照保存在 Spring Boot 数据库，Docker 默认持久化到 `/data`。新建稿会暂存于本浏览器；已有稿请使用“保存材料”。修改原简历或 JD 后需要重新分析。旧版本保留，手动改写也保存为新版本；删除工作稿会删除其所有版本。

分析和生成各发送一次请求到模型设置中的 Provider，复用 Responses 或 Chat Completions 协议，没有后台自动重试。简历、学习对话、资料问答和模型发现共用单请求限流，默认请求完成后间隔 10 秒；重叠任务会提示等待。只有点击分析或生成时才发送简历材料，导入、编辑和导出不调用模型。

网关返回无效 JSON、无法对应的引用或输入中没有的数值时，不保存失败的生成版本；原始材料仍保留。多个浏览器同时改同一个工作稿时通过 revision 检测冲突，避免静默覆盖。

## 参考项目

参考了 [Resume Matcher](https://github.com/srbhr/Resume-Matcher) 的岗位匹配与材料诊断流程，以及 [Reactive Resume](https://github.com/reactive-resume/reactive-resume) 的编辑、版本与导出体验。本功能独立实现，没有复制项目代码。当前导出采用简洁单栏版式，重点是经历内容的质量和可编辑性。

## 验证

Java 集成测试覆盖两种修改流程、材料快照、版本、冲突、无效输出、增强设想、PDF/Word 导入与导出。Playwright 使用本机合成模型服务验证完整浏览器流程、手机布局、打印和草稿恢复，不调用付费模型。
