# 模拟面试

入口为 #/interview。支持题库随机和 JD 定向两种组卷方式，可选择无经验、校招、初级或有经验工程师，并独立设置难度与公司练习场景。

## 开始面试

选择岗位、3–12 道主问题和题型，可填入目标 JD、项目经历或从简历工作区导入材料。

- 题库随机：按岗位关键词与难度检索中文面经和原创问题，搭配本地算法题及原创项目题；开始面试不需要密钥。
- JD 定向：根据 JD、简历和题型，使用当前配置的 GPT 组卷，需要模型网关与密钥。
- 题型包含八股与场景、算法、项目深挖。算法可选择 Java、Go、Python、JavaScript，题库题提供对应模板；已适配题目可运行本地公开样例。

## 判分和追问

AI 按正确性（40）、理解深度（25）、表达（15）和工程判断（20）四项评分，提供回答引用、具体得失和参考思路。所有 AI 判分均需要模型配置，包括题库随机模式。

温和、标准、深挖三档分别允许每个主问题最多 0、1、2 次追问。追问接续候选人的回答，重点检验个人实现、技术取舍、失败场景和验证方法。没有项目材料时先要求介绍亲手完成的项目。

面试模式结束后统一显示评分；练习模式每题提交后显示。可以跳过、提前结束、恢复历史面试；草稿保存在浏览器本机。

## 复盘与算法运行

报告展示平均分、八股/算法/项目分类分数、优势、遗漏和下一轮练习安排，支持 Markdown 导出与打印/PDF。平均分包含已评分的主问题和追问，跳过及未作答单独列出，不计入均分。分数用于训练复盘。

算法运行沿用 Docker 隔离运行器。公开样例通过仅说明本次样例通过，不代表 LeetCode 官方 AC；复杂接口可打开算法工作区或原题。更换代码后需要重新运行，旧运行结果不参与新代码评分。

## 模型与数据

沿用 Codex 风格 TOML、Provider 网关 URL 和模型列表发现功能。模型请求逐个执行，默认前次请求完成后间隔 10 秒；不自动重试，也不自动切换到 DeepSeek。

JD 组卷与 AI 判分会将本场岗位、JD、项目材料及相关回答发送到当前配置的模型网关。历史记录保存在本机数据库；可删除整场面试。公开仓库不包含本地题库正文、个人简历、面试记录或密钥。

## 难度与公司场景

| 难度 | 知识与项目标准 | 算法范围 |
| --- | --- | --- |
| 基础 | 概念、简单应用、本人职责与完整链路；课程/个人项目即可，不要求生产经验 | easy |
| 进阶 | 原理、场景取舍、失败路径、排障与测试 | medium |
| 高阶 | 系统设计、性能容量、故障时序、方案边界和验证证据 | medium / hard |

自动档：无经验、校招或小厂场景默认基础；其余初级默认进阶，有经验默认高阶。手动选择优先。小厂练习侧重基础与交付，中厂侧重模块设计与稳定性，大厂侧重机制、算法与规模假设。这是训练配置，不是企业官方标准，也不意味着公司规模决定题目难度。

标准随本场保存并传给 AI 组卷、评分和追问；追问次数单独配置。基础档选择大厂也不要求生产经验。素材难度由产品规则估计，AI 是否完全遵循仍取决于模型输出。

## 离线面经与检索出题

公开仓库提供 48 条原创演练（MIT），覆盖 Java、Go、Python、前端、AI/Agent、数据库、网络与项目。第三方正文只放本地和私人迁移包。

本地私人包另含经过整理的中文面经，保留公司、岗位、轮次、原帖或固定版本文件链接、作者署名和导入说明。当前本地私人面经包有 4,720 道问题、337 份来源记录；加上公开原创演练后运行时目录显示 4,768 条。题库包含牛客候选人逐轮回忆、博客/PDF 面经以及公司题合集；归档者补写的参考答案不作为标准答案。来源未声明许可证的内容只放在本地私人包，不上传公开仓库。候选人经历和问题未经企业核验，难度由产品按题面估计。详细来源、版本和限制见 `docs/updates/2026-10-15-domestic-interview-memories.md`。

来源：[0voice/Campus_recruitment_interview_questions](https://github.com/0voice/Campus_recruitment_interview_questions)，固定版本 `8b9539fbe3b9239fd512ffb63faa705897db51b1`。上游声明 CC BY-NC-SA 4.0，原作者保留版权。每条保留文件行号链接、署名、修改说明与许可证。仅供本地个人学习，未经逐题核验，不代表企业官方题库。抽取器不导入原答案、视频或联系方式。

复现本地导入（串行执行，不调用模型）：

```sh
git clone https://github.com/0voice/Campus_recruitment_interview_questions.git .cache/content/company-interviews
git -C .cache/content/company-interviews checkout 8b9539fbe3b9239fd512ffb63faa705897db51b1
python scripts/content-import/interview_experiences.py --source .cache/content/company-interviews --output .cache/content/interview-experiences.json
```

将 `DEVPREP_INTERVIEW_EXPERIENCE_FILE` 指向输出 JSON；Docker 需同时挂载文件。私人迁移包已配置。公开版干净启动时仅加载原创题。

本地重建还可使用 `candidate_recollections.py`、`offerseed_interview_experiences.py` 与 `forum_interview_experiences.py`，分别抽取候选人文本/PDF、offerseed 社区投稿及带牛客原帖链接的面经归档。输入仓库须固定到来源说明记录的版本；PDF 导入需安装 `pypdf`。最后用 `merge_interview_experiences.py` 合并现有题库和各本地面经包，现有条目优先，按公司与规范化题面去重。整个流程不请求模型。

JD 模式用本地关键词和技术标签检索：限定难度，排除明显不相关的方向，按相关性与场景侧重排序，同分随机。检索结果作为 few-shot/RAG 上下文提供给 GPT，无需向量库、embedding API 或额外模型请求。模型引用检索 ID 时，服务端拒绝编造或重复的引用；界面与导出报告展示改编来源。同场题目不重复，不足时明确提示；随机项目题使用原创题，避免照搬他人履历。

`GET /api/interviews/catalog` 只返回数量、难度与来源摘要，不返回题面或答案。
